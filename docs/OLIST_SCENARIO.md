# Olist 场景说明：订单、支付、配送与评价助手

确定日期：2026-10-25。状态：业务范围已确定；数据尚未导入，功能尚未实现。详细实施要求见 [B 阶段计划](../STAGE_B_RAG_DETAILED_PLAN.md)。

## 使用者与问题

面向运营分析人员和业务负责人，帮助他们理解字段与指标、核对历史订单表现，并查看每项结论的文档与数据依据。重点解决订单项、支付和评价关联后重复计数，配送日期与时间混用，缺失评价误当低分，以及分析口径不明确的问题。

## 数据与知识来源

采用 [Olist 官方公开数据集](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)的订单、订单项、支付、配送相关字段、评价及客户/商品/卖家维度。它是历史公开数据，不能查询实时业务。先登记下载版本、来源、许可和文件哈希，再核验实际日期覆盖、字段及关联基数。

知识库由数据卡与字段说明、项目指标契约、数据质量说明、分析流程和 FAQ 组成。明确区分官方说明、实测观察和 `project_defined` 自建规范；自建口径和版本演示不代表 Olist 官方制度或历史政策。金额使用 BRL；源时间未确认时区时保留原始日历语义，不自行换算成北京时间。

## 四类任务与首批问题

| 类型 | 代表问题 |
| --- | --- |
| 单文档知识问答 | 已交付订单延迟率怎么计算？缺失交付日期怎么办？ |
| 跨文档比较/流程 | 支付记录金额与商品金额有什么不同？排查差异要核对哪些表？ |
| 项目版本解释 | 延迟率 v1 与演示 v2 的日期判断有哪些变化？按 v1 如何处理同日交付？ |
| 文档与 SQL 联合 | 按 v1 比较 2018 年 1 月下单订单在客户州 SP、RJ 的延迟率和有效样本量。 |

后续联合问题包括：各支付方式的记录金额、各商品类别的已交付订单商品金额、取消订单占比、订单评分与配送表现的描述性关联。日期示例需由导入数据确认覆盖；各指标有独立契约后才进入正式评测。

## 支持范围与边界

支持订单状态和数量、支付方式与记录金额、配送时长与延迟、评分与评价覆盖；按客户州、商品类别、卖家等真实维度分析时明确归属和聚合粒度。首个闭环按客户州计算延迟率，避免多卖家/多类别订单的重复归属。

不支持真实退款流水、退款成功率、扣退款净成交额、利润、库存、活动效果或官网/直播等渠道比较；不新增合成业务表弥补这些缺失。取消不等于退款成功，支付批准不等于到账流水，卖家不等于渠道。静态快照不支持任意过去时点的完整状态重建；配送与评分相关不能证明因果。

## 回答标准与交付顺序

规则结论附文档版本和条款；数字附口径、SQL/结果引用、统计期、范围、单位、有效/排除样本数和快照标识。观察截止时间未知时明确说明；缺条件先澄清，缺证据或数据时说明具体缺失。
