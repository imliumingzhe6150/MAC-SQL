# 订单平均评分、低评分率与评价覆盖率 v1

以下是项目分析口径。低评分阈值和多评价选择策略由本项目明确规定；字段与记录数量见[评价说明](../schema/order_reviews.md)。

## 订单范围

按 `orders.order_purchase_timestamp` 选择 `[period_start, period_end)` 内下单订单，默认只分析快照中状态为 `delivered` 的订单、全部客户州。记录期间、地区范围、`metric_version=1` 和 `db_snapshot`。用户要求全部状态评分时需明确另一个范围，不能静默更换分母。

这批订单称为目标订单群。未评价订单保留在覆盖率分母中，但不参与平均分和低评分率。

## 每单如何选择一条评价

评价表可以一单多行。目标订单内，候选评价须具备整数 1～5 分和可解析的 `review_answer_timestamp`；否则计作无效候选，不参与选择。

按以下键排序，每笔订单取第一条：

1. `review_answer_timestamp` 降序，即最新提交的有效评价优先。
2. 时间相同时按 `review_id` 字典序升序。
3. 仍相同时按 `review_score` 升序，再按原始 CSV 数据行号升序（表头后的第一行为 1）。

这个规则只是确定性选择，不推断多条记录一定是官方修订历史。客户没写标题或正文不会导致评分失效。不要求回答时间晚于交付时间，因为评价流程不是严格的交付后事件日志。

没有有效候选的订单视为“无有效评价”，再区分完全没有评价和只有无效候选，不能记为 0 分。先每单选一次，再按州汇总；禁止 JOIN 订单项后对重复评分求平均。

## definition

| 指标 ID | 名称 | 定义 |
| --- | --- | --- |
| `order_mean_review_score` | 订单平均评分 | 每单选定评分之和 ÷ 有有效评价的目标订单数 |
| `order_low_score_rate` | 低评分订单率 | 选定评分为 1 或 2 分的订单数 ÷ 有有效评价的目标订单数 |
| `order_review_coverage_rate` | 有效评价覆盖率 | 有有效评价的目标订单数 ÷ 全部目标订单数 |

低评分阈值固定为 ≤2，3 分不算低评分。低评分率的分母不是全部已交付订单，也不是全部评价记录。

## 示例与输出

**合成说明例子**：4 笔目标订单，其中 3 笔有选定评分 5、2、1，另 1 笔没有评价。平均分为 8/3 ≈ 2.67，低评分率为 2/3 ≈ 66.67%，覆盖率为 3/4 = 75.00%。示例不是 Olist 实测结果。

输出目标订单数、有有效评价订单数、低评分订单数、无评价订单数、仅无效候选订单数、被选择前存在多条候选的订单数以及三个指标。平均分与百分比显示两位小数（ROUND_HALF_UP），保留未舍入值用于核对。

零有效评价时平均分、低评分率为 null；有目标订单但无有效评价时覆盖率为 0%。目标订单群为空时覆盖率也为 null，说明无可统计订单。

## 和配送一起分析

将已按订单去重的评价与配送结果关联。只研究有效配送且有效评分的交集时，单独报告交集样本量；这不等于全体订单评分。差评与延迟同时出现只能说明相关，不能据此断言延迟导致差评。
