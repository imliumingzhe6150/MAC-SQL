# 第一批开发集的使用方式

先阅读 [20 道题与答案](DEV_QUESTIONS.md)。构成：6 道单文档、4 道跨文档、3 道版本与时间、4 道联合查数、3 道边界题；其中 16 道不需要 SQL。

2026-10-26 修订为 17 道日常问法、3 道版本与时间专项题。用户不必提供指标 ID、表名、SQL 或 v1 标签；系统根据问题与已发布默认口径处理，只有实质缺条件或歧义时才澄清。查数题的范围和已验证数字未变；订单总量由支付题同时检查，利润数据缺失作为边界题。

## 文件职责

| 文件 | 用途 |
| --- | --- |
| `questions.jsonl` | 系统输入：问题 ID、问题、固定请求时间、演示身份；没有答案或预期路由 |
| `gold.jsonl` | 评测标签：任务家族、期望行为、答案要点、禁止误判、证据组和数值结果 |
| `DEV_QUESTIONS.md` | 人工阅读版本，包含答案，不作为系统输入 |
| `manifest.json` | 文档、题集、数据库快照及参考结果的哈希；范围与未覆盖项目 |
| `../reference/dev_numeric_gold.json` | 四道查数题的标准结果和 SQL/知识版本 |

检索输入目录只设为 `knowledge/retail_ops/`，不要递归导入整个仓库。每题独立启动上下文，不能沿用上一题的时间或地区条件。`dev_reader` 是当前演示身份，不表示已经实现权限系统。

本批数值题基于完整 Olist v2 快照；30～50 笔小样本尚未抽取。以后若改用小样本，另存题集与参考结果，不能复用本批数字。

## 怎么判断答对

每题分别记录以下维度，不要求模型逐字复述标准答案：

1. **行为正确**：回答、澄清或说明数据缺失符合预期。澄清题不能先猜一个数值；缺 v2 时不能静默回退 v1。标签中允许的等价路由均可。
2. **内容正确**：覆盖 `reference_facts` 的全部要点，没有 `forbidden_claims` 中的错误。部分覆盖可记录覆盖数，但整题正确记为否。
3. **证据正确**：关键规则有真实文档引用，文档 ID、版本和章节存在且支持结论。每个 `required_evidence_groups` 是一组必需证据，组内 `alternatives` 为可替代来源；不要仅凭提到文档名判正确。若遇到有效但未标注的等价条款，人工复核并记录标签修订。
4. **数值正确**：仅对 dev014～dev017。计数与金额按整数分精确匹配；未舍入比率/均值绝对误差不超过 `1e-12`。面向用户只显示两位小数时，与参考展示值一致即可；原始计数仍须核对。允许字段改名、换行和排序不同，不要求 SQL 文本一致。
5. **表达可用**：先回答用户关心的结论，用日常语言说明必要范围；不要要求用户提供字段名或指标 ID，不为已有默认规则重复澄清。技术细节可放在可展开的依据中，不能只给一段 SQL 或原始 JSON。

查数题应报告题目要求的数值和口径，同时提供实际执行 SQL/结果依据。`score_sum` 等参考字段可作为复算依据；无需要求模型输出实现层字段名。SQL 执行成功单独记录，不等于答案正确。

`headline_numeric_fields` 是主回答应包含的数字，允许用中文表述；其余字段在结构化结果或展开详情中核对，不因主回答没有罗列全部计数而判错。答案要点可由主回答与可查看的依据共同覆盖；必须实际提供这些依据，不能以“后台应该有”为由默认通过。CLI 阶段可以用答案段和依据段表达这种层次，无须等待 Web 界面。

整题通过需同时满足行为、内容、引用及适用的数值要求。报告知识题正确数/16、联合题正确数/4、总正确数/20，并列出每题失败原因；小题集不单独宣称普适性能提升。

表达可用性另列通过数/20，不与数值正确混为一项；回答正确但表达难用的题仍记入待修问题。用户演示就绪需要两项都通过。改写题目并不证明系统已能理解所有自然语言问法，后续仍需实际运行检验。

纯知识题若尚未接入数据库，也可先运行 16 题；必须报告实际分母和跳过的 4 题，不能把未执行题算成通过。本批还没有模型运行结果。

## 证据与版本题说明

章节定位使用仓库相对路径、`doc_id`、版本和原文标题，而不是尚未生成的 chunk ID。后续分块时映射到这些章节。

当前语料只有 v1，因此版本题检验“项目启用时间与历史订单时间的区别”“不存在 v2 时的行为”和“静态快照与历史已知状态的区别”，没有伪造 v2 或冲突文档。真正的新旧版本比较、冲突、权限隔离、文档注入和零分母数值夹具仍需后续补充。本批开发题不是完成整个 B 阶段验收的声明。

题目可以用于改提示词和调检索；不能再将其称为未见测试集。未来独立测试集需按 `family_id` 隔离，不把同一问题换数字或换措辞后放到测试集。

## 重新核算四道数值题

在项目根目录运行：

```bash
python3 evals/retail_ops/reference/build_dev_numeric_gold.py
```

仅使用 Python 标准库，在内存 SQLite 中执行四份参考 SQL，并用直接读取原始 CSV 的 Python 计算交叉核对。原始 CSV 哈希不匹配或结果不一致时会报错。该脚本是参考计算器，不是 RAG 评测器，不调用模型。

参考数据库增加 `price_cents`、`payment_value_cents`、`review_score_int`、`source_row` 等规范化列，时间非法或缺失转为 NULL；这些是计算器内部列，不是原始 CSV 新字段，也不是已交付的业务数据库。金额参考路径会明确拒绝当前快照中不满足解析约定的值，不静默改写数据。

若数据、口径或 SQL 改变，需要重新核算并同步 `gold.jsonl`、人工阅读版及 `manifest.json`；脚本只更新参考结果，不自动覆盖题集标签。
